**14 \- Escenario integral**

Nombre: Raquel Apodaca Caixba  
Grupo: 4-4

La empresa cuenta con una base de datos de 50,000 clientes, los empleados de analítica tienen acceso directo a la tabla completa, los datos se conservan desde hace 12 años sin una política documentada de retención y los desarrolladores reciben copias de producción con información personal real, además, marketing utiliza los correos electrónicos para campañas promocionales sin que exista documentación clara sobre la finalidad de cada dato. Estas condiciones pueden provocar exposición innecesaria de información, usos no justificados y dificultades para controlar el ciclo de vida de los datos.

| Problema | Principio afectado | Riesgo | Control propuesto |
| :---: | :---: | :---: | :---: |
| Todos los empleados de analítica pueden consultar directamente la tabla clientes | Confidencialidad y mínimo privilegio | Acceso innecesario a datos identificables y mayor impacto ante un uso indebido | Crear roles específicos y conceder acceso mediante vistas que contengan sólo los campos necesarios |
| El área de analítica realiza estadísticas mensuales, pero puede consultar nombre, correo, teléfono y rfc | Minimización de datos | Exposición de información personal que no se necesita para generar estadísticas | Proporcionar datos agregados por ciudad, edad u otras categorías justificadas, evitando identificadores directos |
| Los datos se conservan desde hace 12 años sin una política documentada | Limitación del plazo de conservación | Acumulación innecesaria de datos, mayor exposición y dificultad para justificar su conservación | Definir periodos por categoría y finalidad, considerando obligaciones legales y contractuales aplicables |
| No existe una política de retención | Responsabilidad y limitación de la conservación | No hay criterios claros para determinar cuándo revisar, restringir o eliminar datos | Documentar plazos, responsables, excepciones, revisiones y procedimientos de eliminación |
| Los desarrolladores reciben copias completas de la base de datos | Minimización y confidencialidad | Más personas y sistemas pueden acceder a información personal sin necesitarla | Entregar conjuntos reducidos de datos, limitados a las pruebas requeridas |
| Las copias de desarrollo contienen información real | Protección de datos desde el diseño y seguridad | Una fuga o un acceso indebido en desarrollo puede exponer datos de clientes | Utilizar datos ficticios o sintéticos; si excepcionalmente se requiere información real, justificarlo y aplicar controles reforzados |
| Marketing utiliza correos para campañas promocionales sin finalidades documentadas claramente | Limitación de la finalidad y licitud del tratamiento | Uso incompatible con la finalidad original o sin la base jurídica y los requisitos aplicables | Documentar la finalidad, verificar la base jurídica y las autorizaciones o requisitos que correspondan, y gestionar las preferencias de comunicación |
| No está documentada la finalidad de cada dato | Transparencia y limitación de la finalidad | No se puede demostrar por qué se recopila o conserva cada campo ni determinar si es necesario | Crear un inventario de datos con finalidad, responsable, acceso autorizado y plazo de conservación |
| La tabla reúne datos de contacto, identificación y ubicación en un mismo lugar | Minimización y separación de funciones | Un usuario puede acceder a categorías de información que no necesita para su trabajo | Separar lógicamente los datos por finalidad y establecer permisos distintos para cada conjunto |
| No se especifica cómo se revisan los permisos de los empleados | Confidencialidad y responsabilidad | Los permisos pueden mantenerse después de un cambio de puesto o de una necesidad laboral | Revisar periódicamente los accesos y retirarlos cuando dejen de ser necesarios |
| No se menciona un registro de consultas y operaciones sensibles | Responsabilidad y trazabilidad | Puede ser difícil investigar accesos indebidos y determinar qué ocurrió | Registrar accesos y cambios relevantes, proteger los registros y definir quién los revisa |
| No se describe cómo se atienden solicitudes de los clientes sobre sus datos | Derechos de las personas y responsabilidad | Las solicitudes pueden quedar sin atender, retrasarse o ejecutarse sin verificación adecuada | Establecer un procedimiento documentado para recibir, verificar, resolver y registrar solicitudes aplicables |
| No se describe un proceso para eliminar copias de desarrollo cuando dejan de necesitarse | Limitación de la conservación | Las copias pueden permanecer disponibles durante un tiempo indefinido | Inventariar las copias, asignar responsables y aplicar un procedimiento de eliminación verificable al terminar las pruebas |

**Conclusión de la actividad 14**  
El escenario presenta riesgos relacionados con el acceso excesivo, la falta de minimización, la conservación prolongada y el uso de datos sin finalidades claramente documentadas, la empresa debe aplicar controles técnicos y administrativos coordinados para limitar el acceso, reducir la información disponible en cada área, definir periodos de conservación y documentar las decisiones sobre el tratamiento de datos personales.
